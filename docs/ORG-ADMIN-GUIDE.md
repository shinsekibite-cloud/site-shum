# YoungPortal — руководство организации (администратор / владелец)

Актуально: **2026-08-17**.  
Портал для молодёжных организаций: новости, афиша, проекты, клубы, заявки, боты MAX/Telegram, эко-баллы и др. — **модули включаются и выключаются**.

Эталон: https://py.idivles.ru (прод), https://ty.idivles.ru (тест).

---

## 1. Возможности (кратко)

- Публичный сайт + личный кабинет
- Афиша и бронирование пространств, сканер билетов
- Каталоги: проекты, клубы, пространства, места, гранты/добро/самоуправление
- Заявки, сообщения, друзья, уведомления
- Новости, документы, FAQ, вакансии, конкурсы, игры, эко-магазин
- Боты модерации (MAX / Telegram)
- Админка контента + TECH-панель модулей (`/ops`)

## 2. Первый запуск (после установки на VPS)

1. Откройте `https://ВАШ-ДОМЕН/api/health` — должно быть `"ok":true,"db":true`.
2. Учётные данные первого ADMIN: файл на сервере  
   `/etc/yp-portal/admin-credentials.txt`  
   (или те, что задали при установке `--admin-email` / `--admin-password`).
3. Войдите → сразу **смените пароль** и включите **2FA**.
4. Admin → **Контакты и часы**: название, адрес, телефон, режим работы.
5. Admin → **Настройки → Модули** (или попросите TECH на `/ops`): оставьте нужные разделы.
6. Замените демо-контент своими материалами (новости, проекты, клубы).
7. При необходимости: Admin → **Боты** — токены MAX/Telegram и webhook.

Установка «с нуля» одной командой описана в `docs/REMOTE-DEPLOY.md` и `docs/ORG-HANDOFF.md`.

## 3. Специальная админка модулей

| Кто | Где |
|-----|-----|
| ADMIN | `/admin/settings` → вкладка **Модули** |
| TECH | `/ops` (отдельный технический вход) |

Для каждого модуля:

- **Вкл / Выкл**
- Режим при выкл.: «временно отключён» (`hide`) или «в разработке» (`soon`)
- Массово: включить/выключить все публичные

Публичная проверка: `https://ДОМЕН/api/public/status` → поле `modules`.

### Как включать / выключать

1. Откройте панель модулей.
2. Переключите нужный раздел (например «Афиша», «Игры»).
3. Сохраните — кэш сбросится автоматически (до ~минуты на CDN/браузер).
4. Проверьте: выключенный раздел ведёт на `/unavailable`, API отдаёт 503.

При выключении модуль **не удаляет данные** — только скрывает публичный доступ. Включить обратно можно в любой момент.

## 4. Пользователи и права

| Роль | Типичные права |
|------|----------------|
| ADMIN | Полная админка, контент, настройки, модули |
| MODERATOR | Модерация заявок / афиши / контента |
| SCANNER | Сканер входа на мероприятия |
| PARTICIPANT / USER | Кабинет, заявки, запись |
| TECH | `/ops`, флаги модулей, диагностика (env, не БД) |

Создание пользователей: Admin → пользователи / регистрация (если модуль registration включён).

---

## 5. Основные сценарии администратора

1. **Новость** — Admin → Новости → опубликовать.
2. **Мероприятие** — создать пространство → заявку/бронь в афише → модерация.
3. **Проект/клуб** — карточка → заявки участников.
4. **Документ** — Admin → Документы (PDF/DOCX).
5. **Бот** — привязать MAX/TG, проверить webhook, список получателей алертов.
6. **Резервная копия** — попросить TECH или `bash /opt/sochi-portal/scripts/full-backup.sh` на сервере.

---

## 6. Безопасность и бэкапы

- Сильный пароль ADMIN + 2FA
- Не публиковать `/etc/yp-portal/admin-credentials.txt`
- Бэкапы: `/var/backups/sochi-portal/`
- Обновления только через тест-домен → «одобряю» → прод
- Секреты ботов только в `.env` на сервере (права `600`)

Подробнее: `docs/ORG-HANDOFF.md` § безопасность VPS.

## 7. Типичные проблемы

| Симптом | Что сделать |
|---------|-------------|
| 502 / health db:false | `docker ps`, логи web/postgres, место на диске |
| Раздел «отключён» | Модули → включить нужный ключ |
| Не приходит бот | Admin → Боты; webhook URL = ваш домен; CA Минцифры |
| Нет писем | SMTP/Resend в `.env` |
| После установки чужой бренд | Контакты и часы + логотип; демо-карточки удалить |

Контакты сопровождения — по договору передачи.
