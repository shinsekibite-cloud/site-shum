# Защита кода YoungPortal (клиентская поставка)

Полностью запретить правки на VPS, где у заказчика есть root, **нельзя**.
Ниже — практичный уровень, который мы внедряем.

## Что сделано

| Мера | Эффект |
|------|--------|
| `LICENSE` (проприетарный) | Юридический запрет копировать/менять без согласия |
| `--client` kit без `docs/` / tests / qa / workflow | Не отдаём внутреннюю документацию и скрипты разработки |
| `INTEGRITY.json` (sha256 `app.tgz`) | Обнаружение подмены архива до установки |
| `client-harden.sh` | После install: снос docs, `src`/`prisma` → read-only, маркер в `/etc/yp-portal/` |
| Docker-образ из snapshot | Клиент чаще запускает уже собранный image, а не «живёт» в открытом git |

## Чего ждать нельзя

Root на сервере заказчика всегда может снять `chmod`, сделать `docker save`, скопировать файлы.
Это не DRM — это договор + барьер от случайных/лёгких правок.

## Рекомендуемый процесс автору

```bash
# Собрать и опубликовать клиентский комплект
bash scripts/pack-dev-deploy-kit.sh --client --with-live

# Ставить клиенту только --client (не --developer --full)
SSHPASS='…' bash scripts/install-from-url.sh root@IP --client ...
```

Обновления клиенту — только вашими релизами (новый kit / новый image), не правками на его сервере.
